# NEON REVENANT — MSX2 Edition v1.0

**標準Z80のMSX2向け、512 KiB ASCII8 MegaROMの疑似3Dシューティング試作版です。試作中・無保証・実機未検証です。**

turbo R単体版の背景・機体・3区域・3ボスを引き継ぎ、V9938と3.58 MHzのZ80に合わせて描画処理を作り直しました。音楽は標準PSG 3音へ編曲しています。MSX上のROMプログラムとして動作し、PC側での描画やMSX-DOSを使いません。

## 動作環境と起動

| 項目 | 必要な環境 |
| --- | --- |
| 本体 | MSX2、標準Z80 3.58 MHz、RAM 64 KiB以上 |
| VDP | V9938、VRAM128 KiB、SCREEN 4 / 256×192 |
| ROM | 512 KiB、ASCII8マッパー |
| 音源 | 本体標準PSGのみ |
| 映像 | MSX本体の映像出力 |
| 操作 | キーボード、ジョイスティックポート1 |

[ROMはこちら](../outputs/msx2/NEON_REVENANT-MSX2-v1.0.rom)。openMSXではMSX2機種を選び、Cart 1へ**ASCII8**指定で挿入します。映像ソースは**MSX**です。V9990やMSX-MUSICは不要です。

このREADMEのあるソースルートからのWindows PowerShell実行例です。エミュレーターの場所は環境に合わせてください。

```powershell
& 'C:\Program Files\openMSX\openmsx.exe' `
  -machine C-BIOS_MSX2_JP `
  -carta '..\outputs\msx2\NEON_REVENANT-MSX2-v1.0.rom' `
  -romtype ASCII8
```

映像が違う場合はopenMSXコンソールで `set videosource MSX` を指定します。出撃時と区域変更時には約1秒、背景をVRAMへ読み込みます。配布物にBIOSや他のゲームROMを含みません。エミュレーター側に利用可能なシステムROMを用意してください。

今回の検証はC-BIOS MSX2構成をRAM64 KiBへ変更した独立プロファイルです。標準の `C-BIOS_MSX2_JP` はRAM容量が異なります。

## 操作とゲーム内容

| 動作 | キーボード | ジョイスティック1 |
| --- | --- | --- |
| 自機・照準移動 | カーソルキー | 十字方向 |
| ショット・開始・再挑戦 | Space | トリガー1 |
| NOVAボム | X | トリガー2 |
| ポーズ・再開 | Esc | キーボードのEsc |

前方の照準に敵を捉えて連射し、接近する敵と敵弾を避けます。上下移動も可能です。シールド6・ボム3で開始し、シールドが0になるとゲームオーバーです。ボムは敵・敵弾を一掃し、ボスにもダメージを与えます。ボスへの最後の一撃はショットで決めます。

続けて敵を倒すとCHAINが増え、得点が上がります。区域突破でシールドを2、ボムを1補充し、上限はそれぞれ6・3です。ゲームオーバーやクリア直後の短い待ち時間のあと、再出撃できます。ハイスコアは起動中のみ保持します。

| 02 SKYWAY ASSAULT | 工業高架道路 | RAZOR / SIEGE CARRIER |

## MSX2向けに変えたところ

背景と機体の画素データはturbo R単体版と共通です。背景は横8×縦1ピクセルごとに最大2色のSCREEN 4形式で、区域ごとに8枚の前進画像をVRAMへ常駐させます。実行中はVDP表示ページを切り替えます。背景の横揺れはありません。

自機・敵・ボスはスプライトモード2の16×16パターンを2倍表示します。自機は4枚、ボスは12枚のパーツで構成し、色の仕様もturbo R単体版と共通です。

- **VRAMパターンキャッシュ。** 非表示側2面に各64枠を保持し、同じ絵を毎回転送しません。同じ弾はパターンを共有します。そのフレームで使う枠を保護しながら入れ替えます。
- **Z80向けの処理削減。** 色の16バイトコピー・着色をアセンブリ化し、縦座標変換を生成済みの完全一致表へ移しました。HUDは内容が変わった時か一定時間ごとに再構築します。
- **ゲームと描画の時計を分離。** 独自IM2割り込みで60 HzのVBlankを数え、ゲームと音楽を約30 Hzで更新します。重い場面は1描画につき最大3回の論理更新で追従し、ゲーム全体のスローモーションを抑えます。
- **VBlankで表示面を切替。** 処理が期限を超えた時も垂直帰線中であることを確認します。VDP制御の2バイト書き込みと割り込みの状態読取りが衝突しないよう管理しています。
- **PSG専用音楽。** オリジナル曲「Night Current」の区域別メロディーを保持。Aはベース、Bは主旋律、Cはアルペジオと効果音で共有します。FMへのアクセスはありません。

**論理更新は約30 Hzを目標とし、実際の描画・背景の頻度は敵・弾・エフェクトの数で変わります。** 重い場面でも常に30 fpsを保証するものではありません。場面ごとの実測値は検証JSONに記録しています。GIFはMSX側の実測時間どおりの再生速度です。

最終ROMを標準Z80・RAM64 KiBで実行した測定です。移動・連射は各区域64描画の撮影区間、ボスと過密はゲームをポーズした描画負荷試験です。

| 場面 | 実際の描画 | 背景の変化 | ゲーム論理更新 |
| --- | --- | --- | --- |
| 区域1・移動と連射 | 14.64 fps | 13.94 Hz | 29.98 Hz |
| 区域2・移動と連射 | 12.60 fps | 12.60 Hz | 29.80 Hz |
| 区域3・移動と連射 | 12.46 fps | 12.26 Hz | 29.47 Hz |
| 静止ボス・17パーツ | 29.97 fps | ポーズ中 | 停止 |
| 過密配置・32パーツ | 14.55 fps | ポーズ中 | 停止 |

3分のボス継続試験では181.524秒で5,428論理更新を確認し、表示面切替2,362回すべてがVBlank内でした。この継続試験はエミュレーターを無制限速度で進めた耐久確認で、上表の描画性能測定とは分けています。

同じ走査線のパーツが8枚を超えると、その瞬間は一部が表示されません。全画面でも32枚までです。優先順位を巡回させるため、集中する場面ではちらつきます。高速化でこのVDP上限が増えるわけではありません。

## ビルド

Python 3、Pillow、NumPy、Z80用SDCC、Pasmoが必要です。再生成に必要な原画データ・素材・字体は `assets/source` に保存しているため、このMSX2版だけでもビルドできます。

```powershell
# このREADMEのあるフォルダーから実行
python -m pip install -r requirements.txt
$env:SDCC_BIN = 'D:\Tools\sdcc\bin'
$env:PASMO = 'D:\Tools\Pasmo\pasmo.exe'
python tools/build.py
```

成果物はソースルートの1つ上の `outputs/msx2`、中間生成物は版専用の `work/build` です。SDCC本体は `SDCC`、付属コマンド一式は `SDCC_BIN` で場所を指定できます。コンパイラーやエミュレーターのバイナリーは同梱しません。

| ROM内の範囲 | 内容 |
| --- | --- |
| 00000–01FFF | ASCII8起動コード |
| 02000–07FFF | RAMへコピーして実行するコード |
| 08000–0FFFF | 113パーツ・5,650バイトのスプライトと余白 |
| 10000–2FFFF | 区域1、8ページ×16 KiB |
| 30000–4FFFF | 区域2、8ページ×16 KiB |
| 50000–6FFFF | 区域3、8ページ×16 KiB |
| 70000–73FFF | タイトル画面16 KiB |
| 74000–7FFFF | 未使用領域 |

実行コードは8000–DFFF、データはE000以降です。IM2ベクトルをEE00–EF00、ジャンプをEFEFへ配置し、F000–F2FFをスタック用に確保しています。領域重複はビルド時に検査します。

## 検証と制限

openMSX 21.0、V9938・VRAM128 KiB・RAM64 KiB・標準Z80で検証。スプライト制限は有効、描画精度はpixelです。実機や実カートリッジでの動作は未検証です。

- [ゲーム動作](../outputs/msx2/verification.json): 起動、4方向、連射、ボム、ポーズ、被弾、再挑戦、3区域のボス出現・撃破・遷移・クリア。
- [背景と実測映像](../outputs/msx2/world-verification.json): 各区域103,424バイトのVRAM読戻し、PSG更新、論理・描画・背景の頻度、GIF画素と表示時間。
- [スプライト](../outputs/msx2/sprite-verification.json): 非表示2面のVRAM内容、17枚と32枚の描画、100フレームにわたる優先順位・パターン入替。
- [PSG](../outputs/msx2/sound-verification.json): 音程、音量、効果音、ミュートと復帰、I/O方向の保持。
- [時計と表示切替](../outputs/msx2/timing-verification.json): 約3分のボス動作、全表示面切替のVBlank監査、IM2ベクトルとスタック。
- [元版保持・再現ビルド](../outputs/msx2/scope-verification.json): ゲーム進行16関数と背景・機体データの一致、独立フォルダーでの完全再生成。

ボス、被弾、過密場面などはRAMへ状態を設定した試験です。その後の入力・衝突判定・描画・状態遷移はROMコードが実行します。最初から最後までの手動プレイスルーとは区別しています。

開発用の64 KiBプロファイルは `python tools/setup_emulator.py` で準備できます。出力された `OPENMSX_HOME` と `OPENMSX_USER_DATA` を設定し、`node tools/emulator_host.mjs -carta <ROMのパス> -romtype ASCII8` で専用エミュレーターを起動します。HTTP制御先はローカルの18802番です。`tools/emu.py` で起動状態を設定した後、`tools/verify_rom.py`、`tools/verify_sprites.py`、`tools/verify_world.py`、`tools/verify_timing.py` を順に実行できます。ゲーム動作試験の前はROMをリセットしてください。
