# NEON REVENANT 音楽更新周期の修正版（ローカル検証用）

対象: MSX2（PSG）、Turbo R単体（FM＋PSG）、Turbo R＋V9990通常版、V9990機能試験版。
描画ループでの音源更新を60Hz VBlank割り込みからの約30Hz更新に変更しました。
曲・効果音の音源処理そのもの、背景素材、敵、ゲーム進行の仕様は変更していません。
全ROMは512 KiB / ASCII8です。MSX1 v1.4はすでに対応済みのため変更していません。

## 検証

openMSXによる全4版×3ステージのRAM設定シナリオ試験です。
- sound_tick入口の間隔: 約33.376ms（NTSC実周波数に従う約29.96Hz）。
- 主処理をRAM上のループに置き換えて2秒停止: 音楽更新は約60回継続。
- ROMから展開された全ステージの背景VRAMが元の素材と一致。
- 左移動、ポーズ、消音、再開、ボム消費を確認。FMのキーオフも確認。
- ROMの素材領域（0x8000以降）が公開版と全バイト一致。
- 最終ソース再ビルドのROMがエミュレーター検証対象と一致。

物理ジョイスティック・実機・PAL機は未検証です。操作試験はキーボード入力で実施。
試作版・無保証。GitHubの公開版はまだ差し替えていません。

## 実装

MSX2は既存のIM2割り込みに統合。Turbo R系はF400..F500のIM2ベクタと
F5F5..F5F7のジャンプを使用し、E800..EFFFの展開履歴とF300から下向きの
スタックを保持しています。BIOSワークを再利用するため、初期化後にBIOSを
呼び出す将来の変更では見直しが必要です。
V9990版の時計は本体VDPから取得し、IRQはV9990のポートに触れません。
PSGのジョイスティック読取りと音源状態変更は短い割り込み禁止区間で保護。
全対象はVDPを60Hzに設定するため、MSX1版の50/60Hz分数カウンタは不要です。

## ソースと再ビルド

作業ブランチ: audio-clock-fix。ベース: c699abb。
変更ソースと差分、検証JSONを同梱しています。
既存のビルド手順で tools/build.py、msx2/tools/build.py、turbor/tools/build.py、
v9990-feature-lab/tools/build.py に --pack-only を付けて再ビルドできます。
検証ツール tools/verify_audio_clock.py はローカルopenMSX Tclブリッジ（18801）を使用します。
BIOS、エミュレーター、コンパイラは同梱しません。
