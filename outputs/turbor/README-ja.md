# NEON REVENANT — Turbo R Edition v1.0

> **試作中・無保証 / Experimental prototype — AS IS, WITHOUT WARRANTY.** 実機・実カートリッジは未検証です。利用前に[免責事項](../../DISCLAIMER.md)と、リポジトリ直下の利用条件・第三者ライセンスを確認してください。

**MSX turbo R本体だけで動く、512 KiB ASCII8 MegaROMの疑似3Dシューティングです。** 内蔵V9958のSCREEN 4を使い、V9990カートリッジを必要としません。MSX本体側の映像出力に表示します。ゲームはMSX上のネイティブプログラムとして動き、MSX-DOS、PC側の描画処理、外部素材の読み込みは使いません。

V9990版の「夜のサイバー都市を疾走する」動きと、3区域・3ボスのゲーム内容を、標準VDPの色とスプライトの制約に合わせて移植しています。道路、建物の面、窓、看板が手前へ移動・拡大する背景を使用します。元のV9990版は別の成果物として保持します。

## 必要な環境

| 項目 | 内容 |
| --- | --- |
| 本体 | MSX turbo R。Panasonic FS-A1ST / FS-A1GTを想定 |
| VDP・VRAM | 本体内蔵V9958、128 KiB VRAM |
| ゲームカートリッジ | 512 KiB / 524,288バイト、ASCII8マッパー対応カートリッジまたは対応ROMローダー |
| 映像 | MSX本体側の映像出力 |
| 音源 | 本体内蔵MSX-MUSICとPSG |
| 操作 | キーボード、またはジョイスティックポート1の2ボタンコントローラー |

配布ROMは`outputs/turbor/NEON_REVENANT-TurboR-v1.0.rom`です。V9990版ROMとはファイル名と使用する映像出力が異なります。

## openMSXで起動する

openMSXの機種を**Panasonic_FS-A1ST**に設定し、**Cart 1にTurbo R版ROMをASCII8として挿入、Cart 2は空**にしてください。V9990 / GFX9000拡張は追加しません。映像ソースは**MSX**です。

このREADMEがあるソースフォルダーを作業ディレクトリにする場合の、Windows PowerShellでの起動例です。

```powershell
& 'C:\Program Files\openMSX\openmsx.exe' `
  -machine Panasonic_FS-A1ST `
  -cart '..\outputs\turbor\NEON_REVENANT-TurboR-v1.0.rom' `
  -romtype ASCII8 `
  -command 'set videosource MSX'
```

openMSXとROMのパスは実際の配置に合わせて変更してください。起動中に映像ソースを選ぶ場合は、F10でコンソールを開いて次を入力し、もう一度F10で閉じます。

```tcl
set videosource MSX
```

タイトル画面でSpaceまたはトリガー1を押すと出撃します。背景素材をVRAMへ転送する間は表示を切り替えます。区域の背景転送はopenMSX実測で約1.2秒です。

利用者が用意したシステムROMを、既存のopenMSX環境から使用してください。配布物にBIOSや他のゲームROMは含みません。

## 操作とゲーム内容

| 動作 | キーボード | ジョイスティック1 |
| --- | --- | --- |
| 自機と照準の移動 | カーソルキー | 十字方向 |
| ショット・ゲーム開始 | Space | トリガー1 |
| NOVAボム | X | トリガー2 |
| ポーズ・再開 | Esc | キーボードのEsc |
| ゲームオーバー後の再挑戦 | Space | トリガー1 |
| クリア後の再出撃 | Space | トリガー1 |

ショットは押し続けると連射します。前方の照準に敵を捉え、敵弾と接近する敵機を避けて進みます。自機は上下にも移動できます。ゲームオーバー・クリア直後は短い待ち時間があり、その後に再出撃できます。

- シールド6、ボム3で開始します。シールドが0になるとゲームオーバーです。
- NOVAボムは敵と敵弾を一掃し、ボスにもダメージを与えます。ボスへの最後の一撃はショットで決めます。
- 短い間隔で敵を倒すとCHAINが増え、得点が上がります。回復アイテムはシールドを1回復します。
- 区域突破時はシールドを2回復、ボムを1補充します。上限はそれぞれ6と3です。
- 3区域目のボスを倒すとクリアです。ハイスコアは起動中に保持します。

| 区域 | 舞台 | ボス |
| --- | --- | --- |
| 01 CHROME DISTRICT | ネオンの市街地 | WARDEN / INTERCEPTOR |
| 02 SKYWAY ASSAULT | 工業高架道路 | RAZOR / SIEGE CARRIER |
| 03 THE BLACK SPIRE | 中枢トンネル | NOX / CENTRAL CORE |

ゲームルール、敵の進行、ボス構成、操作、オリジナル楽曲と効果音を引き継いでいます。音楽はMSX-MUSIC、ショット・爆発・被弾・ボムなどの効果音はPSGで鳴らします。

## V9990版との違い

以下はVDPの全機能ではなく、**それぞれのゲームが採用している構成**の比較です。

| 項目 | V9990版 | Turbo R Edition |
| --- | --- | --- |
| 追加グラフィックス機器 | V9990カートリッジ | 不要、内蔵V9958 |
| 映像出力 | V9990側 | MSX本体側 |
| 表示モード | B1、256×212 | SCREEN 4、256×192 |
| パレットの選択範囲 | RGB各5ビット、32,768色から選択 | RGB各3ビット、512色から選択 |
| 採用パレット | 16色 | 16色 |
| 背景の色配置 | 4bpp、各ピクセルに色を指定 | 横8×縦1ピクセルの区間ごとに最大2色 |
| 区域ごとの背景 | 16フレーム | 8フレーム |
| 背景の保持 | 区域の画像をV9990 VRAMへ展開 | 区域の8ページを128 KiB VRAMへ転送 |
| 自機・敵など | V9990の画像コピーで合成 | スプライトモード2、16×16パターンをMAG2で32×32表示 |
| スプライト表示数 | V9958のスプライト枚数制限を使わない | 全画面32枚、同じ走査線には最大8枚。合成用パーツも各1枚として数える |
| 音源 | MSX-MUSIC + PSG | MSX-MUSIC + PSG |
| ROM容量 | 512 KiB | 512 KiB |

SCREEN 4の背景は色を使える単位が粗いため、金属の陰影や細かなネオンの色分けを整理しています。自機とボスは各行に2色を使う重なりのない2枚のスプライト面で構成し、一般の敵は各行1色です。敵の暗い内部を抜きにして、翼、中心部、砲口を判別しやすくしています。

スプライトが集中して1走査線8枚を超えると、一部のパーツや弾がその瞬間に表示されません。同等の優先度を持つ敵などの順序を入れ替えて固定的な欠落を避けるため、重なりの多い場面ではちらつきが発生します。これは背景の8×1ピクセルの色制約とは別の制限です。これらの背景形式・スプライト数と倍率は、[Yamaha V9938 Technical Data Book](https://map.grauw.nl/resources/video/yamaha_v9938.pdf)のGRAPHIC 2/3およびSPRITE MODE 2の記述に基づきます。V9958の512色パレット、走査線ごとのスプライト色などは[V9958 Technical Data Book](https://map.grauw.nl/resources/video/yamaha_v9958_ocr.pdf)も参照してください。

**通常の移動・射撃とボス表示は約30 Hz、背景は約15 Hzです。** openMSXのMSX側時間で測定しました。ボス・弾14発・敵9機を同時に置く過密試験では描画が約20 Hzになりました。背景の横揺れは省略し、前進する8枚の画像の切り替えに集中しています。HUDは上下の文字表示へ再構成し、区域名・ボス耐久力・ポーズ・クリアなどを表示します。

## ソースからビルドする

このREADMEのあるディレクトリが移植版のソースルートです。

```text
src/                 C・Z80アセンブリのゲームとVDPドライバー
tools/               スプライト変換・背景変換・ビルド用Python
assets/source/       再生成用に保存した原画データ・パレット・文字
assets/sprites.bin   変換後のハードウェアスプライト
assets/world/        SCREEN 4背景ページとプレビュー
work/build/          ビルド中間ファイル
```

再ビルドには**Python 3、Pillow、NumPy、Z80ターゲット対応SDCC、Pasmo**が必要です。SDCCとPasmoの実行ファイル、MSXのシステムROMはソース配布に含めません。同梱の`assets/source`に必要な入力を保存しているため、通常の再生成にV9990版の作業フォルダーは必要ありません。

Windows PowerShellで、このREADMEのあるフォルダーへ移動して実行します。

```powershell
python -m pip install Pillow numpy

# 利用者の環境にあるツールの場所を指定
$env:SDCC_BIN = 'D:\Tools\sdcc\bin'
$env:PASMO = 'D:\Tools\Pasmo\pasmo.exe'

# スプライト・背景の再生成からコンパイル、ROM組み立てまで実行
python tools/build.py
```

`SDCC_BIN`は`sdcc.exe`と関連実行ファイルがあるディレクトリ、`PASMO`は`pasmo.exe`のフルパスです。必要なら`SDCC`でコンパイラー本体のフルパスを指定できます。Windows用SDCCでは`sdcc.exe`だけでなく、プリプロセッサーなどの付属ファイルも配置してください。

`SDCC_BIN`を省略した場合、この開発環境ではソースルートの1つ上にある`work/toolchain/sdcc/bin`を探します。単独で展開したソース配布ではその配置がない場合があるため、上記の環境変数による指定を使ってください。`PASMO`を省略した場合はPATH上の`pasmo`を使用します。

ビルドは、現在のソースルートの**1つ上の`outputs/turbor`**に次を生成します。

- `NEON_REVENANT-TurboR-v1.0.rom` — 524,288バイト固定のASCII8 ROM。
- `build-manifest.json` — ROMと各区域素材の容量、配置、SHA-256。

この作業環境の元の配置では、これが`outputs/turbor/NEON_REVENANT-TurboR-v1.0.rom`に相当します。中間ファイルは移植版自身の`work/build`へ保存します。

## ROM・描画データの構成

| ROM内の範囲（16進） | 内容 |
| --- | --- |
| 00000–01FFF | 起動コード、ASCII8バンク0 |
| 02000–07FFF | MSX内蔵RAMへ転送して実行するゲームコード |
| 08000–0FFFF | スプライト用領域、未使用部分は0xFF |
| 10000–2FFFF | 区域1、8ページ×16 KiB |
| 30000–4FFFF | 区域2、8ページ×16 KiB |
| 50000–6FFFF | 区域3、8ページ×16 KiB |
| 70000–73FFF | タイトル画面、16 KiB |
| 74000–7FFFF | 0xFF埋め |

背景はSCREEN 4のパターン・色・配置テーブルへ変換済みのページです。区域に入る際に8ページを転送し、実行時に表示ページを選びます。この移植版のROMでは背景ページをそのまま格納しており、V9990版のLZSS展開処理は使いません。

スプライトは47種類の描画対象を113枚のハードウェアパーツへ変換し、データは5,650バイトです。各パーツは符号付き相対位置2バイト、16×16のパターン32バイト、行ごとの色16バイト、合計50バイトで保持します。自機は4枚、ボスは12枚を使います。これは同時表示数ではなく、それぞれ1機を構成するパーツ数です。

## 検証の状態

素材変換では、元データのハッシュ、レコードから復元した画素との一致、2枚の色面が重ならないこと、色番号の範囲、ROM容量上限を確認しています。変換後のスプライトは`assets/sprites-preview.png`、詳細な構成は`assets/sprites-manifest.json`で確認できます。生成素材の検証は、実行中のVDP表示やゲーム全体の検証とは区別します。

openMSX 21.0のPanasonic_FS-A1STで、V9990拡張なし、ASCII8、標準V9958映像、R800 DRAM動作、スプライト枚数制限有効・pixel精度の条件で検証しました。

- タイトルから開始、上下左右、連射、ボムの押下判定、ポーズと再開、被弾、ゲームオーバー、再挑戦を確認。
- 3区域それぞれのボス出現・撃破・次区域への移行、最終クリアを確認。
- 各区域の背景テーブル103,424バイトをVRAMから読み戻し、生成データと照合。書き換えるHUDとスプライト領域は別途扱っています。
- 3区域それぞれ64フレームを実行中のエミュレーターから撮影。GIFは実際のMSX時刻に合わせ、全フレームの画像一致も確認。
- スプライトのパターン・色・属性テーブルをRAMとVRAM間で照合。ボス17枚で約29.96 Hz、過密32枚で約19.97 Hzを確認。横一列に8枚を超えると部分欠落することも確認。
- 区域転送後もMSX-MUSICのレジスターが更新されることを確認。音源コードとゲーム進行16関数はV9990版から変更していません。
- 素材の全再生成を含むビルドで同じROMハッシュになることを確認。元のV9990 v1.2 ROMもハッシュ一致で保持を確認。

検証結果は配布先の `verification.json`、`world-verification.json`、`sprite-verification.json`、`scope-verification.json` にあります。遠い区域・ボス最終一撃・被弾・過密場面はRAMに状態を設定した試験です。入力、衝突判定、状態遷移、描画はROMのコードを実行しており、最初から最後までの手動プレイスルーとは区別しています。

実機および実カートリッジへの書き込み後の動作確認は、まだ行っていません。BIOS・システムROMは利用者が用意し、配布物には含めません。
